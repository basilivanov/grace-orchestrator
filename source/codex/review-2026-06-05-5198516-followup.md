## Verdict

This push fixes most of the runtime issues from the previous review. The code now has real changes for merge-to-MERGED, ClaimResult DTO, cancel via PacketService, wave gate stop semantics, SQLite column migration, worktree-aware T0, and git worktree cleanup.

However, **one important issue remains open**:

> `MergeService.merge_packet()` still swallows state-transition failure and returns `MergeResult(success=True)`.

That means the original bad behavior is reduced but not fully eliminated: the service now calls the correct transition (`PacketState.MERGED`), but if DB transition fails, API can still report merge success while DB state did not change.

## Checked items

### 1. Merge transition uses `PacketState.MERGED`

Status: partially fixed.

Good:

```python
await svc.transition(
    packet_id, PacketState.MERGED, reason=f"merge_complete:{commit_sha[:8]}",
)
```

Remaining issue:

```python
except Exception as e:
    _log.warn("merge_state_transition_failed", ...)
...
return MergeResult(True, ...)
```

If transition fails, merge still returns success.

Required final fix:

```python
try:
    await svc.transition(packet_id, PacketState.MERGED, reason=f"merge_complete:{commit_sha[:8]}")
except Exception as e:
    _log.warn(...)
    return MergeResult(False, packet_id, commit_sha, str(repo), branch_name, target_branch,
                       error=f"state transition failed: {str(e)[:200]}")
```

Add regression test: injected `PacketService.transition()` failure must produce `MergeResult(success=False)`.

### 2. SQLite migration for `features.degraded_reason`

Status: fixed.

`init_db()` now calls `_run_sqlite_column_migrations(engine)` after `create_all()`, with an idempotent additive migration:

```python
("features", "degraded_reason", "ALTER TABLE features ADD COLUMN degraded_reason TEXT")
```

Tests added for old SQLite schema and idempotency.

### 3. `PacketService.claim()` detached ORM risk

Status: fixed.

`claim()` now returns frozen `ClaimResult` DTO instead of ORM `Lease`.

Router reads:

```python
result.packet_id
result.spec
result.lease_id
result.expires_at
result.attempt
```

No detached ORM access in claim response path.

### 4. `cancel_packet()` through `PacketService`

Status: mostly fixed.

Router now delegates to `PacketService.cancel()` and translates `PacketNotFoundError` / `StateTransitionError` to HTTP.

`PacketService.cancel()` handles transition, lease removal, worker cleanup and terminal state checks.

Small future cleanup: observability is duplicated a bit — service broadcasts, then router also records/broadcasts best-effort. Not a blocker, but later should be unified to avoid duplicate events.

---

### 5. `wave_gate` no longer opens after `BLOCKED_FINAL`

Status: fixed.

`done_states` now only includes:

```python
{PacketState.MERGED, PacketState.CANCELLED}
```

`BLOCKED_FINAL` is in degraded states. This prevents final-blocked waves from opening the next wave.

---

### 6. T0 lint checks worktree paths

Status: fixed.

`_build_t0_commands()` / `_resolve_t0_scope_paths()` now accept `cwd`, and `_run_t0()` passes `cwd or self._root`. Candidate paths are resolved against actual command cwd/worktree root, not project root.

---

### 7. Worktree cleanup uses `git worktree remove`

Status: fixed in router merge path.

`GitService` now has:

```python
worktree_remove(...)
worktree_prune(...)
```

`MergeService.cleanup_worktree()` calls git removal/prune when `target_repo_root` is provided, then falls back to `shutil.rmtree()`.

Router passes `target_repo_root`, so the API merge path is covered.
