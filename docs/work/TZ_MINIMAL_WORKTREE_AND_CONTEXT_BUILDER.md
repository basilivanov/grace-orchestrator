# TZ: Minimal worktree and context builder for agent runs

Date: 2026-06-10
Status: draft
Priority: P0 live-test blocker
Scope: agent execution infrastructure

## 1. Problem

Live agent tests (`backend-1w`, `resume-t2-failure`) consistently fail because the API process is killed by OOM during agent runs.

Root cause: the worker creates a git worktree from the **full project root**. `opencode run` loads the entire project into memory (thousands of files, 73GB VSZ), causing 4GB+ RSS. This triggers the OOM killer, which kills the API process.

The fix in `process_supervisor.py` (oom_score_adj=1000, ulimit) helps but does not eliminate crashes because `opencode run` still uses too much memory before the OOM killer can react.

## 2. Goal

Prevent OOM by reducing the agent's memory footprint at the source.

Two complementary changes:

1. **Minimal worktree**: the worker creates a worktree containing ONLY the files relevant to the task (the fixture app + tests), not the entire project.
2. **Context builder**: the agent profile or runner provides a minimal prompt/context file that references only the fixture app, so `opencode run` does not scan thousands of irrelevant files.

## 3. Non-goals

Do not change the acceptance pipeline or state machine.
Do not change the packet lifecycle.
Do not remove existing worktree behavior for non-live-test scenarios.
Do not change the admin UI.

## 4. Required changes

### 4.1 Worker: minimal worktree mode

The worker's `_call_executor` creates a worktree via `git worktree add` from the project root.

Add a mode where, instead of the full project worktree, the worker creates a **minimal isolated git repo** with only the fixture app files.

Controlled by a new setting:

```python
# In agent profile or packet spec:
minimal_repo: true
# or env var:
GRACE_AGENT_MINIMAL_REPO=true
```

When enabled, the worker:

1. Creates a temp directory
2. `git init` with only the fixture files
3. Sets up a minimal `pyproject.toml` if needed
4. Uses this directory as the worktree instead of `git worktree add`

The fixture files path comes from the packet's scope:

```yaml
scope:
  - tests_live/fixtures/apps/backend_fastapi_todo/main.py
  - tests_live/fixtures/apps/backend_fastapi_todo/tests/test_api.py
```

The worker detects the fixture root from the scope paths and copies only those files.

### 4.2 Context builder: skip context collection for explicit waves

When waves are submitted explicitly (not generated by architect), the agent does not need full project context.

Add a profile flag or env var:

```yaml
profiles:
  coder-opencode:
    skip_context_builder: true
```

When enabled, the packet materializer does NOT run the context builder (which reads git history, project structure, etc.). Instead it generates a minimal execution packet containing:

- The task prompt from the scenario YAML
- The fixture app file contents (inlined or as file references)
- The verification commands

### 4.3 Runner: pass minimal_repo flag to API

The test runner (`wave_resume_runner.py`) already submits the feature spec with `verification` and `scope`. Add the `minimal_repo` flag to the packet spec when the scenario requires it.

## 5. Implementation plan

### Step 1: Add `minimal_repo` to agent profile / packet spec

In `agent_profiles.yaml`:

```yaml
coder-test-flash:
  backend: cli
  minimal_repo: true
  skip_context_builder: true
  command: [opencode, run, --model, '{model}', --dir, '{worktree_path}']
  input:
    mode: stdin
    template: '{packet_markdown}'
```

In `packet_executor.py:_resolve_executor`, propagate `minimal_repo` from profile to the execution request.

### Step 2: Worker creates minimal repo

Add a new method `_create_minimal_repo(scope_paths, target_dir)` in `packet_executor.py` or a new service.

Implementation:

```python
def _create_minimal_repo(self, scope_paths: list[str], target_dir: Path) -> Path:
    repo = target_dir / "repo"
    repo.mkdir(parents=True, exist_ok=True)
    git = GitService()
    git._run(["init", "-q", str(repo)])
    git._run(["-C", str(repo), "config", "user.email", "agent@grace"])
    git._run(["-C", str(repo), "config", "user.name", "Grace Agent"])
    for scope_path in scope_paths:
        src = Path(scope_path)
        if src.exists():
            dst = repo / src.name
            shutil.copy2(src, dst)
    git._run(["-C", str(repo), "add", "."])
    git._run(["-C", str(repo), "commit", "-q", "-m", "init"])
    return repo
```

### Step 3: Agent profile uses minimal prompt

The `coder-test-flash` profile (or the existing `coder-opencode`) should generate a prompt that only references the fixture files, not the full project.

The prompt template in the scenario YAML already does this — it says "Add PATCH /items/{id}/done to `main.py`" without mentioning other project files.

### Step 4: Test

Run `backend-1w` with the new profile and verify:

- API does not die from OOM
- Agent produces changes
- T0/T1 pass
- summary.json shows `real_agent_runs >= 1`
