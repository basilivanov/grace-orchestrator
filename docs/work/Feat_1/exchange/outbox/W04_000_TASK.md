# Task: W04 — Execution Packet Context Bundle for Coder

Implement the wave spec:

`docs/work/Feat_1/waves/W04_EXECUTION_PACKET_CONTEXT_BUNDLE.md`

## Goal

Coder must not work blindly. `EXECUTION_PACKET.md` must include enough target-repo context, constraints, tests, verification commands, evidence requirements, and workspace diagnostics for reliable execution.

## Allowed scope

- `src/grace_control/services/packet_materializer.py`
- `src/grace_control/services/agent_workspace_builder.py`
- `src/grace_control/services/packet_executor.py`
- `src/grace_control/services/agent_run_service.py`
- `src/grace_control/services/context_collector.py`
- `tests/`
- `docs/work/Feat_1/`

Do not refactor unrelated lease/recovery/profile/prompt code in this wave.

## Required implementation

### 1. Enrich `EXECUTION_PACKET.md`

Rendered packet must include these sections:

1. Objective
2. Business requirement
3. Role and non-goals
4. Allowed write scope
5. Frozen scope
6. Relevant file tree
7. Selected file previews
8. Nearby tests
9. Config/build files available
10. Import/dependency hints
11. Coder instructions
12. Acceptance criteria
13. Verification commands by T0/T1/T2
14. Full expected evidence fields
15. Workspace mode and limitations
16. Target repo root diagnostics
17. Full spec JSON dump

### 2. Block blind NORMAL/STRICT code packets

NORMAL/STRICT coder packets must not launch if required context is missing, unless the packet explicitly sets:

```yaml
context_not_required: true
```

Missing context should produce a clear blocked/rejected state or materializer/preflight error, not a silent low-context run.

### 3. Scoped copy/config allowlist

Scoped workspace/context must include files needed for targeted verification:

- `pyproject.toml`
- `pytest.ini`
- `setup.cfg`
- `tox.ini`
- `mypy.ini`
- ruff config
- `package.json`
- lockfiles
- `tsconfig*`
- vite/vitest/playwright configs
- `conftest.py`
- `.env.example`

Never copy `.env`.

### 4. CWD/worktree safety

Stop silently creating a missing cwd/worktree path in agent execution. Missing cwd must fail visibly with diagnostics.

## Required tests

- `test_execution_packet_contains_file_tree_and_previews`
- `test_execution_packet_renders_full_evidence_requirements`
- `test_normal_packet_requires_context_or_explicit_override`
- `test_scoped_copy_includes_required_config_allowlist`
- `test_agent_run_fails_if_cwd_missing_instead_of_creating_it`
- `test_coder_profiles_all_have_input_mode_or_packet_arg`

## Acceptance criteria

W04 is accepted only if:

1. NORMAL/STRICT coder packets get actionable context.
2. Missing context blocks execution unless explicitly overridden.
3. `EXECUTION_PACKET.md` includes all required sections.
4. Evidence requirements are rendered with full structured fields, not only IDs/prose.
5. Scoped workspace includes relevant source, nearby tests, and config allowlist files.
6. `.env` is never copied.
7. Missing cwd does not get silently created.
8. Tests prove the above.
